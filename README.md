# 🟢 QueueX - 스마트 웨이팅 시스템

> “줄이 아닌, 가장 적합한 고객을 호출하는 시스템”

---

## 📌 프로젝트 소개

QueueX는 기존 웨이팅 시스템의 단순 순번(FIFO) 방식에서 발생하는 비효율을 개선하기 위해 개발된  
**매장 운영 정책 기반 스마트 웨이팅 시스템**입니다.

기존 웨이팅 시스템은 보통 FIFO 방식으로 대기 목록을 보여주기 때문에,  
회전율이 중요한 매장에서는 관리자가 현재 수용 가능한 인원에 맞는 손님을 직접 찾아 호출해야 하는 불편함이 있습니다.

즉, 관리자 입장에서는 대기 목록을 하나씩 확인하면서  
“지금 2명이 들어갈 수 있으면 어느 팀을 불러야 하는지”,  
“단체석이 비었을 때 어떤 팀을 먼저 불러야 하는지”를 직접 판단해야 하고,  
이 과정에서 좌석이 남아 있어도 바로 입장 가능한 손님을 놓치거나 운영 흐름이 비효율적으로 흘러갈 수 있습니다.

QueueX는 이러한 문제를 해결하기 위해 다음 정책과 추천 로직을 함께 반영했습니다.
- 매장 좌석 수 / 한 팀 최대 이용 가능 인원 관리
- 일반석 / 단체석 분리 운영
- 인원수 기반 추천과 FIFO를 함께 고려한 호출 방식
- 선주문, 주문 수량 제한, 품절 메뉴 처리

즉 QueueX는 단순히 “줄을 서는 시스템”이 아니라,  
👉 **관리자가 FIFO 목록에서 대기번호를 직접 찾는 대신, 매장 상황에 맞는 추천 손님을 바로 호출할 수 있도록 설계한 웨이팅 시스템**입니다.

## 고객 플로우

고객을 선택하면 전화번호와 비밀번호를 통해 로그인 또는 회원가입을 진행합니다.

```text
전화번호 입력 >>
비밀번호 입력 >>
```

- 고객 전화번호는 `PhoneNumberUtil.normalize()` 기준으로 숫자만 저장합니다.
- 고객 비밀번호는 평문 저장이 아니라 해시값으로 저장합니다.
- 로그인 시 입력한 평문 비밀번호를 해시 비교로 검증합니다.

로그인 성공 후 고객 메뉴는 아래 흐름으로 진행됩니다.

```text
[고객 메뉴]
1. 가게 선택
2. 내 대기 조회
0. 종료
```

### 1. 가게 선택
- 가게 목록을 보여주고 원하는 가게를 선택합니다.
- 가게 목록에서 매장의 좌석 수와 한 팀 최대 이용 가능 인원을 함께 확인할 수 있습니다.
- 가게 선택 후 해당 가게 메뉴를 조회할 수 있습니다.
- 메뉴 화면에서 `B`를 입력하면 가게 선택 화면으로 돌아갈 수 있습니다.
- 같은 가게에 이미 `WAITING` 또는 `CALLED` 상태 대기가 있으면 중복 등록할 수 없습니다.
- 메뉴는 품절 여부를 숨기지 않고 `품절` 상태로 출력합니다.

### 2. 대기 등록
- 가게 선택 후 대기 등록을 선택합니다.
- 인원수를 입력합니다.
- 인원수 입력 후 선주문을 진행합니다.
- 메뉴 입력 중 현재 주문내역과 총 주문 수량을 계속 확인할 수 있습니다.
- 같은 메뉴를 다시 입력하면 수량이 누적됩니다.
- `메뉴번호 0` 형식으로 입력하면 해당 메뉴를 주문내역에서 삭제할 수 있습니다.
- 총 주문 수량이 최대치에 도달하면 자동으로 주문내역 확인 단계로 이동합니다.
- 주문내역 확인 화면에서:
  - `1. 대기 등록 진행`
  - `2. 주문 수정`
  - `0. 가게 선택으로 돌아가기`
  를 선택할 수 있습니다.
- 매장의 `max_capacity`(매장 좌석 수)를 초과하는 인원은 대기 등록할 수 없습니다.
- 매장의 `max_group_size`(한 팀 최대 이용 가능 인원)를 초과하는 인원은 대기 등록할 수 없습니다.
- 선주문 총 수량은 `max_group_size`와 동일한 기준으로 제한됩니다.
- 품절 메뉴는 조회되지만 선택할 수 없습니다.
- 대기 등록 완료 후 가게명, 대기번호, 인원수, 등록 시각, 주문내역을 출력합니다.

### 3. 내 대기 조회
- 현재 대기 중인 가게명, 대기번호, 대기 순서, 인원수, 안내 문구, 주문내역을 조회합니다.
- 대시보드 화면은 자동 갱신되며, 상태나 순서가 실제로 바뀐 경우에만 다시 출력됩니다.
- 현재 구현에서는 `WAITING`, `CALLED` 상태를 현재 대기 현황으로 조회합니다.
- 일반 손님(`1~5명`)은 `일반 대기 순서`, 단체 손님(`6명 이상`)은 `단체 대기 순서` 기준으로 조회합니다.
- 내 대기 조회 화면 안에서 대기 취소를 진행할 수 있습니다.

### 4. 대기 등록 취소
- 별도 메인 메뉴가 아니라 `내 대기 조회` 화면 안에서 진행합니다.
- 취소할 대기를 현재 대기 현황과 유사한 카드형 정보로 확인한 뒤 선택합니다.
- `Y/N` 확인 후 상태를 `CANCELED`로 변경합니다.
- `Y/N` 외 입력 시 재입력을 요구합니다.

## 관리자 플로우

관리자를 선택하면 관리자 인증 절차를 진행합니다.

```text
관리자 인증번호 입력 >>
```

- 입력한 인증번호는 해시 비교를 통해 검증합니다.
- 로그인은 최대 3회까지만 시도할 수 있습니다.
- 인증 성공 후 관리자 메뉴로 이동합니다.

```text
[관리자 메뉴]
1. 가게 선택 및 운영
2. 통계 조회
0. 로그아웃
```

### 1. 가게 선택 및 운영
- 관리자 본인에게 속한 가게 목록만 출력합니다.
- 가게를 선택한 뒤 현재 대기 목록을 조회합니다.
- 일반석 운영은 `1~5`를 입력합니다.
- 6인 이상 단체석 운영은 `G`를 입력합니다.
- 일반석 입력값은 해당 매장의 `max_capacity`(매장 좌석 수)를 초과할 수 없습니다.
- 일반석 추천은 입력한 인원수 기준으로 추천 순위를 계산합니다.
- 단체석 운영은 `6명 이상` 대기 손님만 FIFO 기준으로 추천합니다.
- 추천 가능한 손님이 없으면 전체 FIFO 대기 목록을 참고용으로 보여줍니다.
- 다음 손님을 호출하거나 취소할 수 있습니다.

### 2. 호출 이후 처리
- 호출 완료 후 현재 호출 고객을 보여줍니다.
- 이후 아래 동작을 선택할 수 있습니다.
  - 입장 처리
  - 노쇼 처리
- 호출된 대기는 반드시 입장 또는 노쇼로 마감합니다.
- 입장 또는 노쇼 처리 후에는 현재 좌석 상황에 맞게 수용 인원을 다시 입력합니다.
- 입장 / 노쇼 완료 메시지는 다음 운영 화면 제목 위에 배너 형태로 다시 보여줍니다.

### 3. 통계 조회
- 가게를 선택한 뒤 아래 통계 유형을 선택합니다.
  - `1. 오늘 통계`
  - `2. 전체 통계`
  - `0. 뒤로 가기`
- 가게 선택 화면에서 `0`을 입력하면 관리자 메뉴로 돌아갑니다.
- 통계 항목은 총 방문 고객 수, 총 웨이팅 수, 메뉴별 주문 건수, 노쇼 건수를 포함합니다.
- 오늘 통계는 `created_at = CURDATE()` 기준입니다.
- 전체 통계는 누적 데이터 기준입니다.

## 공통 입력 규칙

### 전화번호 처리 기준
- 전화번호는 `PhoneNumberUtil`을 통해 공통 처리합니다.
- DB 저장 시에는 `normalize()`를 사용하여 숫자만 저장합니다.
  - 예: `010-1234-5678` → `01012345678`
- 화면 출력 시에는 `format()`을 사용하여 하이픈 포함 형식으로 보여줍니다.
  - 예: `01012345678` → `010-1234-5678`
- 전화번호 입력 검증은 `isValid()` 기준으로 처리합니다.

### 인증값 처리 기준
- 고객 비밀번호와 관리자 인증번호는 모두 해시값으로 저장합니다.
- 로그인 시에는 사용자가 입력한 평문 값을 해시 비교로 검증합니다.
- 공통 인증 비교는 `PasswordUtil` 기준으로 처리합니다.

## 🧠 핵심 로직

### 📌 인원수 기반 고객 추천
관리자 → 수용 인원 입력
→ 대기 고객 중 조건 만족 고객 필터링
→ FIFO 기준으로 우선순위 정렬
→ 추천 리스트 출력

✔ 단순 순번이 아닌  
👉 **“입장 가능한 고객 우선” 구조**

### 📌 일반석 / 단체석 분리
- 일반석 운영: `1~5` 입력
- 단체석 운영: `G` 입력
- 고객 대기 순서도 일반 / 단체 레인 기준으로 분리하여 표시합니다.

### 📌 매장 운영 정책
- `store.max_capacity`
  - 해당 매장이 보유한 전체 좌석 수입니다.
- `store.max_group_size`
  - 한 팀이 이용할 수 있는 최대 인원입니다.
- 선주문 제한
  - 총 주문 수량 기준으로 제한하며, 현재는 `max_group_size`와 동일하게 적용합니다.
- 품절 메뉴 처리
  - 메뉴를 숨기지 않고 출력하되, 선택 시 서비스 로직에서 차단합니다.

## 빌드 및 실행

로컬 Maven 컴파일:

```bash
mvn compile
```

패키징:

```bash
mvn clean package
```

JAR 실행:

```bash
java -jar target/queuex-1.0-SNAPSHOT-jar-with-dependencies.jar
```

직접 `javac`를 출력 경로 없이 실행하면 `.class` 파일이 소스 폴더 옆에 생성될 수 있으므로, 기본적으로 Maven 명령(`mvn compile`, `mvn package`)을 사용합니다.

## Docker 실행

Compose 파일 구성:
- `docker-compose.yml` : 배포용, `app`은 Docker Hub 이미지(`miju03/queuex-app:latest`) 사용
- `docker-compose.dev.yml` : 개발용 override, `app`을 로컬 `Dockerfile` 기준으로 build
- `docker-compose.shared.yml` : 공용 DB 접속용 override, `app`이 지정된 공유 MySQL 서버를 사용

MySQL만 백그라운드로 실행:

```bash
docker compose up -d mysql
```

앱 실행:

```bash
docker compose run --rm app
```

초기 스키마와 테스트 데이터는 `docker/mysql/init/` 아래 SQL 파일이 자동 실행됩니다.

주의:
- `app`은 웹 서버가 아니라 콘솔 입력형 프로그램입니다.
- 따라서 `docker compose up -d app`처럼 상시 서비스로 띄우는 방식보다 `docker compose run --rm app`으로 실행하는 것이 맞습니다.
- Docker Desktop에서 `app` 컨테이너가 종료 상태로 보일 수 있는데, 이는 입력 종료 후 정상적으로 끝난 상태입니다.

앱 로그 확인:

```bash
docker compose logs -f app
```

DB 로그 확인:

```bash
docker compose logs -f mysql
```

DB를 초기화부터 다시 시작하려면:

```bash
docker compose down -v
docker compose up -d mysql
docker compose run --rm app
```

### 개발용 Docker 실행

로컬 코드 수정본으로 `app` 이미지를 직접 빌드해 실행하려면:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

### 배포용 Docker 실행

Docker Hub에 올린 이미지를 그대로 사용하려면:

```bash
docker compose up
```

### 공용 DB(공유 MySQL) 사용

한 대의 노트북 또는 서버에서 MySQL을 공용으로 띄우고, 다른 기기들이 같은 DB를 보도록 실행할 수 있습니다.

- DB 서버 역할 기기:

```bash
docker compose up -d mysql
```

- 다른 기기:

```bash
git pull
docker compose pull
docker compose -f docker-compose.yml -f docker-compose.shared.yml run --rm app
```

현재 `docker-compose.shared.yml`은 `192.168.0.8:3309`의 공용 DB를 보도록 설정되어 있습니다.

### Docker Hub 이미지 업데이트

- `docker push`는 compose 파일 전체를 올리는 것이 아니라, **직접 지정해서 push한 이미지 태그만** 업로드합니다.
- 예를 들어 아래 명령은 배포용 이미지 하나만 올립니다.

```bash
docker buildx build --platform linux/amd64,linux/arm64 -t miju03/queuex-app:latest --push .
```

- 개발용 태그까지 올리고 싶을 때만 별도로 build/push 해야 합니다.

```bash
docker build -t miju03/queuex-app:dev .
docker push miju03/queuex-app:dev
```

## 다른 컴퓨터에서 실행

다른 컴퓨터에서도 Docker만 설치되어 있으면 아래 순서로 실행할 수 있습니다.

```bash
git pull
docker compose pull
docker compose -f docker-compose.yml -f docker-compose.shared.yml run --rm app
```
